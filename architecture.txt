Localhost — Rust HTTP Server: Architecture Plan
Design Philosophy

Single-threaded, non-blocking I/O via epoll event loop
State machine per connection — each connection tracks its own parse/write state
Zero-crash guarantee — all errors propagated, never panicked on client input
Modular crates-within-project structure for testability

  - Initialize logger

  - Hand off to event_loop::run()

event_loop/epoll.rs
struct Epoll { fd: RawFd }

impl Epoll
  fn create() -> Result<Self>
  fn add(fd: RawFd, events: u32, token: u64) -> Result<()>
  fn modify(fd: RawFd, events: u32, token: u64) -> Result<()>
  fn delete(fd: RawFd) -> Result<()>
  fn wait(events: &mut [EpollEvent], timeout_ms: i32) -> Result<usize>
event_loop/registry.rs
struct Registry
  fn register_listener(fd, server_id)
  fn register_connection(fd, ConnectionState)
  fn get_connection_mut(fd) -> Option<&mut ConnectionState>
  fn remove(fd)
  fn all_connection_fds() -> Vec<RawFd>
event_loop/dispatcher.rs
fn run(epoll: Epoll, registry: Registry, configs: Vec<ServerConfig>) -> !
  - Main loop: epoll.wait() → dispatch each event
  - EPOLLIN on listener fd → accept_new_connection()
  - EPOLLIN on conn fd     → read_from_connection()
  - EPOLLOUT on conn fd    → write_to_connection()
  - EPOLLERR/HUP           → close_connection()
  - Per-tick: check_timeouts()

fn accept_new_connection(listener_fd, epoll, registry)
fn read_from_connection(fd, epoll, registry, configs)
fn write_to_connection(fd, epoll, registry)
fn close_connection(fd, epoll, registry)
fn check_timeouts(registry, epoll)

server/connection.rs
enum ConnectionPhase
  ReadingHeaders
  ReadingBody { bytes_read, expected }
  ReadingChunked { chunk_state }
  Processing          ← synchronous handler runs here
  WritingResponse { bytes_written }
  AwaitingCgi { child_pid, pipe_fd }
  Done

struct ConnectionState
  fields: fd, phase, read_buf, write_buf, request Option<Request>,
          response Option<Response>, server_id, last_activity Instant,
          peer_addr

impl ConnectionState
  fn new(fd, server_id, peer_addr) -> Self
  fn advance(&mut self, configs) -> Result<StateTransition>
  fn is_timed_out(&self, timeout: Duration) -> bool

const READ_TIMEOUT: Duration
const WRITE_TIMEOUT: Duration
const CGI_TIMEOUT: Duration

fn check_all(registry: &mut Registry, epoll: &Epoll, timeout: Duration)

  - Sends 408 if still in reading phase

router/matcher.rs

  - Longest prefix match
  - Exact match takes precedence

fn dispatch(request: &Request, route: &RouteConfig, server: &ServerConfig)
  -> Result<Response>

  - Checks redirect
  - Checks CGI extension
  - Delegates to handlers::*

handlers/static_file.rs
fn serve(request: &Request, route: &RouteConfig) -> Result<Response>
  - Resolves URL path to filesystem path via route root
  - Path traversal safety check
  - Reads file, resolves MIME type
  - Returns 200 with body or 404
handlers/upload.rs
fn handle(request: &Request, route: &RouteConfig, size_limit: usize)
  -> Result<Response>
  - Validates Content-Type: multipart/form-data or application/octet-stream
  - Writes file to configured upload directory
  - Returns 201 Created
handlers/directory.rs
fn list(fs_path: &Path, url_path: &str) -> Result<Response>
  - Reads directory entries
  - Renders HTML index listing
  - Returns 200
handlers/error.rs
fn render(code: u16, custom_page: Option<&str>) -> Response
  - Reads custom error page if configured
  - Falls back to built-in default HTML

cgi/executor.rs
fn spawn(script_path: &Path, request: &Request, route: &RouteConfig)
  -> Result<CgiProcess>
  - fork() + exec() the interpreter
  - Sets up stdin pipe (request body) and stdout pipe (response)
  - Returns CgiProcess with child pid and pipe fds

struct CgiProcess
  fields: pid, stdin_fd, stdout_fd

fn poll_output(proc: &CgiProcess) -> Result<CgiPollResult>

  - CgiPollResult: Pending | Complete(Vec<u8>) | Error

utils/mime.rs

Key Data Flow
epoll event
    │
    ▼
dispatcher::run()
    │
    ├─ Listener fd  ──► accept() ──► new ConnectionState ──► register EPOLLIN
    │
    └─ Connection fd
           │
           ├─ EPOLLIN  ──► read into read_buf
           │               ──► request::parser::parse_request_head()
           │               ──► body::read_body_*()
           │               ──► router::matcher::select_server()
           │               ──► router::matcher::match_route()
           │               ──► router::handler::dispatch()
           │                       │
           │                       ├─ static  ──► handlers::static_file
           │                       ├─ upload  ──► handlers::upload
           │                       ├─ delete  ──► handlers::delete
           │                       ├─ dir     ──► handlers::directory
           │                       ├─ cgi     ──► cgi::executor::spawn()
           │                       │               ──► register CGI stdout_fd in epoll
           │                       └─ error   ──► handlers::error
           │               ──► response::writer::serialize() → write_buf
           │               ──► re-arm EPOLLOUT
           │
           └─ EPOLLOUT ──► response::writer::write_nonblocking()
                          ──► if done: check Connection header → close or keep-alive

Cargo.toml Dependencies
toml[dependencies]
libc = "0.2"          # epoll, fork, socketpairs, syscalls

[dev-dependencies]
reqwest = { version = "0.12", features = ["blocking"] }   # integration tests
Everything else — HTTP parsing, event loop, CGI, sessions — is written from scratch. No tokio, hyper, actix, or nix.

What's Next
When you're ready to start coding, a good build order is:

config/ — parse and validate a config file
event_loop/epoll.rs + server/listener.rs — accept connections
http/request/parser.rs — parse raw bytes into Request
router/ + handlers/static_file.rs — serve a GET request end-to-end
http/response/writer.rs — non-blocking writes
server/connection.rs state machine + server/timeout.rs
handlers/upload.rs, handlers/delete.rs
cgi/ module
session/ + session/cookie.rs
Stress tests with siege
